## 2. 번개장터 — 수집 가능

### robots.txt (m.bunjang.co.kr, 2026-07-09 실측)
```
User-agent: *
Allow: /
Disallow: /talk2
```
`/talk2`(번개톡, 채팅)만 금지. 나머지 전체 허용, 사이트맵 공개.

### 확인된 접근 경로
- 검색 API: `api.bunjang.co.kr/api/1/find_v2.json?q=<검색어>&n=<건수>&page=<페이지>&order=date` — **무인증 JSON** 반환 (실측 확인).
- 응답 필드: `pid`(매물 ID), `name`, `price`, `location`(구·동 단위 지역!), `update_time`(unix), `product_image`, `status`, `used`, `category_id`, `num_faved` 등 — 정규화 `Listing` 스키마에 필요한 필드 대부분이 목록 응답에 이미 포함.
- 상세 페이지: `m.bunjang.co.kr/products/<pid>` — 본문·이미지 전체는 상세에서 획득.
- 비고: `location` 필드가 있어 번개장터도 **지역 필터가 부분적으로 가능** (전국 검색 후 지역 텍스트 매칭).

### 수집 전략
`order=date`로 최신순 폴링 → 마지막 수집 `update_time` 이후 신규분만 상세 조회. Watch당 30분 주기, 요청 간 2~5초 지연.

### 리스크
- 비공식 API — 예고 없는 스키마 변경/차단 가능. 어댑터 격리 + 헬스체크(FR-D4)로 대응.
- Phase 1 대상 플랫폼으로 확정 (계획서 §7과 일치).

## 3. 중고나라 (자체 웹) — 조건부 가능

### robots.txt (web.joongna.com, 2026-07-09 실측)
```
User-agent: *
Disallow: /my-account, /naver-pay-result, /product/form, /*?openChat=true, /signin
Allow: /
Sitemap: https://web.joongna.com/sitemap-product-index.xml.gz
Sitemap: https://web.joongna.com/sitemap-keyword.xml.gz
```
계정·결제·글쓰기 경로만 금지. **상품/키워드 사이트맵을 공개 제공** — 검색 노출을 원하는 구조로, 목록·상세 열람은 허용 범위.

### 확인된 접근 경로
- 검색 페이지: `web.joongna.com/search/<키워드>` — Next.js App Router(RSC flight data, `self.__next_f`)로 렌더 (실측 확인). `__NEXT_DATA__` JSON 블록은 없음.
- 수집 옵션 (Phase 2 스파이크에서 택1):
  1. RSC flight 데이터 파싱 (HTML 1회 요청으로 목록 확보, 파서 유지보수 부담)
  2. 브라우저 개발자 도구로 내부 검색 API 관찰 후 직접 호출 (구조 변경에 취약하나 구현 단순)
  3. Playwright RPA로 렌더된 DOM 파싱 (가장 견고, 리소스 소모 큼) — **폴백 경로**
- 사이트맵 기반 신규 매물 발견도 보조 경로로 검토 가능.

### 리스크
- 카페 발원 매물이 자체 웹에 얼마나 노출되는지 미검증 (커버리지 리스크). 중고나라는 카페→앱 전환을 수년간 진행했으므로 자체 웹 커버리지가 높다고 가정하되, Phase 2에서 표본 검증.
- 봇 차단(Cloudflare 등) 여부는 지속 수집 시점에 재확인 → 차단 시 옵션 3(RPA)으로 전환.

## 4. 당근마켓 — 조건부 가능 (허용 경로만 사용)

### 4.1 robots.txt (www.daangn.com, 2026-07-09 실측)
```
User-agent: * 그룹:
Disallow: /kr/buy-sell/s/*      ← 중고거래 "검색" 경로 금지
Disallow: /kr/realty/s/*, /kr/cars/s/*, /kr/jobs/s/* ... (각 버티컬 검색 경로 금지)
Disallow: /ad/, /admin, /wv/
(AI 크롤러 UA 목록은 /kr/ 전체 금지)
```
**핵심**: 금지는 `s/*`(검색) 경로에 집중. 지역 브라우즈 피드 `/kr/buy-sell/?in=<동네>-<지역ID>`는 금지 목록에 **없음** (실측: HTTP 200).

### 수집 전략 — 검색이 아니라 "지역 피드 구독"
robots가 금지한 검색 경로는 사용하지 않는다. 대신:
1. 사용자 Watch의 지역(동 단위)에 해당하는 **지역 브라우즈 피드**를 주기 수집 (허용 경로)
2. 키워드/모델 매칭은 **우리 파이프라인의 검색엔진 필터(①단계)가 로컬에서 수행**

이 방식은 아키텍처와도 정합적이다 — 어차피 별칭 매칭은 자체 검색엔진이 담당하므로, 플랫폼 검색 기능에 의존할 필요가 없다. 지역 피드는 신규 매물이 시간순으로 노출되므로 폴링 수집에 적합.

### 리스크
- 웹 노출 매물이 앱 대비 부분집합일 가능성 (**Q1 미해결** — Phase 2에서 앱 대비 표본 비교로 검증).
- 페이지가 SSR/하이드레이션 구조일 경우 파싱 방식 결정 필요 (HTML 파싱 vs RPA) — Phase 2 스파이크.
- 지역 ID(`역삼동-6035` 형식) 매핑 테이블을 구축해야 함: 행정동명 → 당근 지역 ID. 최초 1회 수집·캐시.

## 7. 자동 채팅(FR-D6) 리스크 평가 — Q6 예비 판정

| 플랫폼 | 채팅 경로 | 예비 판정 | 근거 |
|---|---|---|---|
| 번개장터 | 번개톡 (웹 `/talk2`) | ⚠️ **고위험** | **robots.txt가 `/talk2`를 명시 금지** — 자동화에 대한 명확한 거부 신호. 계정 제재 가능성 높음 |
| 당근마켓 | 앱 중심 채팅 (웹 채팅 제한적) | ⚠️ **고위험** | 웹 로그인/채팅 경로 자체가 제한적, 전화번호 기반 본인 계정 — 제재 시 실사용 계정 손실 |
| 중고나라 | 웹 채팅 (`?openChat=true`) | ⚠️ **고위험** | robots.txt가 `/*?openChat=true` 금지 |

**예비 결론**: 3사 모두 채팅 경로가 명시적으로 자동화 거부 신호를 보이고 있어, **완전 자동 발송은 권장하지 않음**. FR-D6은 다음으로 조정 권고:
- 기본 형태를 "**반자동**"으로: 알림의 [문의 보내기] 버튼 → 시스템이 **문의 메시지 초안을 생성해 클립보드/딥링크로 제공** → 사람이 앱/웹에서 1탭 발송. (계정 제재 리스크 0, 자동화 가치의 대부분 유지)
- 완전 자동(RPA 로그인 발송)은 본 조사 승인자(발주자)가 계정 제재 리스크를 명시적으로 감수하는 경우에만, 부계정 검토와 함께 Phase 3에서 재평가.
