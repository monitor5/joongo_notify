# 02. 기능 요구서 (Functional Requirements Specification)

- 프로젝트명: joongo_notify
- 문서 버전: v0.2 (초안)
- 작성일: 2026-07-09
- 상태: 검토 대기
- 관련 문서: [01-project-plan.md](01-project-plan.md) — **확정된 전제(개인 1인용, 저빈도 수집, 자동 채팅 포함/자동 구매 제외)는 계획서 상단 참조**

## 표기 규칙

- **ID**: `FR-<영역>-<번호>` (기능), `NFR-<번호>` (비기능)
- **우선순위**: `P0` 없으면 MVP 불성립 / `P1` Phase 2 목표 / `P2` Phase 3 이후
- 각 요구사항은 **수용 기준(AC)** 을 가지며, AC가 검증 가능해야 완료로 인정

---

## A. 사용자 및 Watch 관리

### FR-A1. 웹 로그인 (자체 인증) — P0
Watch 관리는 웹 UI에서 하며, 접근은 **자체 인증**으로 보호한다: 설정 파일/환경변수에 정의된 단일 계정(ID/PW), 세션 쿠키 방식. 개인 1인용이므로 회원가입 기능은 없다.
- **AC**: 미로그인 상태에서 모든 관리 화면·API가 로그인 페이지로 리다이렉트됨.
- **AC**: 비밀번호는 해시로 저장(평문 설정 금지), 로그인 실패 5회 시 일시 잠금.
- **AC**: 외부 노출 배포 시 HTTPS 필수 (역프록시 문서화 — `31-operations.md`).

### FR-A1a. 카카오 OAuth 로그인 — P1
카카오 디벨로퍼스 개인 앱을 등록해 카카오 로그인으로도 진입할 수 있게 한다. 허용된 카카오 계정 ID(본인)만 통과.
- **AC**: 등록된 본인 카카오 계정 외의 로그인 시도는 거부됨.
- **AC**: 자체 인증(FR-A1)과 병행 동작 (카카오 장애 시 대체 진입 경로).

### FR-A1b. 텔레그램 알림 채널 연결 — P0
알림 수신용 텔레그램 chat_id를 웹 설정 화면에서 등록한다 (봇에게 `/start` 후 표시되는 연결 코드 입력 방식).
- **AC**: 연결 완료 시 테스트 알림이 수신됨.

### FR-A2. Watch 등록 — P0
사용자는 웹 UI 폼에서 감시 항목을 등록한다: ① 제품 선택(검색) → ② 상태 조건 입력 → ③ 가격 범위 → ④ 지역(당근마켓용, 선택) → ⑤ 확인.
- **AC**: 등록 완료 시 요약(제품/조건/가격/지역)이 표시됨. 필수값 누락 시 해당 필드 검증 오류 표시.
- **AC**: 조건은 카테고리의 속성 스키마(FR-B2)에서 파생된 선택지로 입력 (자유 텍스트는 P2의 FR-A6).

### FR-A3. Watch 목록·수정·일시정지·삭제 — P0
- **AC**: 웹 목록 화면에서 자신의 Watch 전체 조회. 각 항목에서 일시정지/재개/삭제 가능. 일시정지 중에는 알림이 오지 않으나 수집·분석 이력은 유지.

### FR-A4. 조건의 필수/선호 구분 — P0
각 상태 조건은 **필수(hard)** 또는 **선호(soft)** 로 지정한다. 필수 위반 매물은 알림 제외, 선호는 점수에만 반영.
- **AC**: "번인 없음(필수), 풀박스(선호)" Watch에서 번인 명시 매물은 알림되지 않고, 박스 없는 매물은 감점된 채 알림됨.

### FR-A5. 지역 조건 — P0
당근마켓 Watch에는 기준 지역(동 단위)과 반경 수준을 지정한다. 중고나라/번개장터는 전국 + 선택적 지역 텍스트 필터.
- **AC**: 당근마켓 수집이 지정 지역 파라미터로 수행됨을 로그로 확인 가능.

### FR-A6. 자유 텍스트 조건 입력 — P2
"번인 없고 잔기스 정도는 괜찮아요, 박스 있으면 좋고" 같은 자연어를 LLM이 구조화 조건으로 변환하고 사용자가 확인한다.
- **AC**: 변환 결과를 사용자가 수정·승인한 뒤에만 저장.

## B. 카탈로그 (카테고리·제품·속성 온톨로지)

### FR-B1. 계층형 카테고리 정의 — P0
카테고리는 트리 구조(예: 전자제품 > 스마트폰)이며 데이터 파일(YAML)로 관리한다. 초기 범위: 스마트폰, 모니터, 노트북.
- **AC**: YAML 수정만으로 카테고리 추가 가능 (코드 변경 불필요).

### FR-B2. 카테고리별 상태 속성 스키마 — P0
각 카테고리는 상태 속성 집합을 정의한다: 속성명, 타입(열거/수치/불리언/리스트), 허용값, 시각검증가능 여부(VL 대상 여부).

예 — 스마트폰:
| 속성 | 타입 | 값 | 시각검증 |
|---|---|---|---|
| 번인 | 열거 | 없음/약함/심함/언급없음 | ✅ |
| 외관기스 | 열거 | 없음/생활기스/눈에띔/파손/언급없음 | ✅ |
| 배터리효율 | 수치(%) | 0–100/언급없음 | ❌ |
| 침수이력 | 불리언 | 예/아니오/언급없음 | ❌ |
| 구성품 | 리스트 | 박스/충전기/케이블/영수증 | ✅(부분) |
| 잔여보증 | 수치(개월) | 0+/언급없음 | ❌ |

- **AC**: 모든 열거형 속성에 `언급없음` 값이 존재. LLM 추출 스키마(FR-C2)가 이 정의에서 자동 생성됨.

### FR-B3. 제품 카탈로그와 별칭 사전 — P0
제품은 정식명 + 별칭 리스트(한/영/축약/오타 변형)를 가진다. 예: `iPhone 14 Pro` = 아이폰14프로, 아이폰 14 pro, iP14P, 아이폰14 프로 256.
- **AC**: 별칭 사전에 등록된 어떤 표기로 게시된 매물도 검색엔진 필터(FR-C1)를 통과함.
- **AC**: 별칭 추가는 데이터 파일 수정으로 가능하며 재색인이 자동 수행됨.

### FR-B4. 미탐 신고 기반 별칭 보강 — P1
사용자가 "이 매물이 안 잡혔다"고 URL을 제보하면, 시스템이 제목을 분석해 별칭 후보를 제안한다.
- **AC**: 제보된 매물의 미탐 원인(별칭 누락/조건 판정 오류)이 분류되어 기록됨.

## C. 수집 및 분석 파이프라인

### FR-C0. 플랫폼 어댑터 인터페이스 — P0
모든 플랫폼 수집기는 공통 인터페이스(검색어+지역 → 원시 매물 목록, 매물 ID → 상세)를 구현한다.
- **AC**: 새 플랫폼 추가 시 어댑터 1개 구현 외에 파이프라인 코드 변경이 없음.
- **AC**: 어댑터는 플랫폼별 레이트리밋 설정(분당 최대 요청 수)을 강제 준수.

### FR-C1. 신규 매물 수집 및 정규화 — P0 (번개장터) / P1 (당근·중고나라)
스케줄러가 활성 Watch의 검색 키워드로 주기 수집하고, 통합 `Listing` 스키마로 정규화·저장한다. 이미 처리한 매물은 재분석하지 않는다.
- **AC**: 동일 매물 재수집 시 신규 레코드가 생기지 않음 (플랫폼+매물ID 유니크).
- **AC**: 수집 주기는 Watch 단위 설정 가능하되 **기본 30분, 최소 15분** (저빈도 운영 전제 — 주기를 15분 미만으로 줄이는 설정은 거부).

### FR-C2. LLM 본문 상태 추출 — P0
경량 로컬 LLM이 매물 제목+본문에서 카테고리 속성 스키마에 맞는 JSON을 추출한다. 각 속성에 근거 문장을 첨부한다.
- **AC**: 출력이 스키마 검증을 통과 (실패 시 1회 재시도 후 `분석실패` 마킹).
- **AC**: 본문에 정보가 없는 속성은 반드시 `언급없음` (환각으로 값을 만들지 않음 — 골든셋으로 검증).
- **AC**: 골든셋 추출 정확도 ≥ 85%.

### FR-C3. VL 사진 검증 — P1
필수/선호 조건 중 시각검증가능 속성에 대해, 본문에 언급이 없거나 본문 주장을 검증할 필요가 있을 때 VL 모델이 사진을 분석한다. 출력: 속성값 + 신뢰도(low/med/high) + 근거 사진 인덱스.
- **AC**: VL 실행은 ①②단계 통과 매물로 한정됨 (실행 건수 로그로 확인).
- **AC**: 본문 주장과 사진 판정이 상충하면 `상충` 플래그가 매칭 결과에 표시됨.

### FR-C4. 교차 플랫폼 중복 제거 — P1
제목·가격·이미지 지각해시(pHash) 유사도로 동일 매물을 묶는다.
- **AC**: 동일 매물 다중 플랫폼 게시 시 알림이 1회만 오고, 알림에 전체 플랫폼 링크가 병기됨.

### FR-C5. 매칭 스코어링 — P0
Watch 조건 × AnalysisReport → 0~100점. 규칙: 필수 위반=탈락, 선호 충족=+가점, `언급없음`=소감점(탈락 아님), VL 신뢰도가 낮으면 가중치 축소.
- **AC**: 점수 산출 내역(속성별 판정·근거)이 저장되어 알림과 UI에서 조회 가능.
- **AC**: 스코어링은 순수 함수로 구현되어 단위 테스트로 규칙별 검증.

## D. 알림 및 운영

### FR-D1. 텔레그램 알림 발송 — P0
임계점수(기본 60, Watch별 설정) 초과 매물을 즉시 발송. 내용: 대표 사진, 제목, 가격, 지역, 플랫폼, 점수, **속성별 판정 요약과 근거**, 원본 링크.
- **AC**: 신규 매물 저장 → 알림 도달까지 5분 이내 (분석 큐 대기 포함).
- **AC**: 동일 매물이 같은 Watch로 중복 알림되지 않음.

### FR-D2. 알림 피드백 — P1
알림 메시지에 [👍 맞음 / 👎 아님 / 🔕 이 매물 무시] 버튼 제공.
- **AC**: 피드백이 MatchResult에 기록됨 (P2에서 튜닝 재료로 사용).

### FR-D3. 가격 변동 감지 — P2
이미 알린 매물의 가격 인하를 감지해 재알림한다.
- **AC**: 인하 폭이 설정 임계(기본 5%) 이상일 때만 재알림.

### FR-D4. 수집기 헬스체크 — P1
어댑터별 연속 실패(구조 변경·차단)를 감지하면 운영자에게 알린다. **조용한 실패 금지.**
- **AC**: 어댑터가 N회(기본 5) 연속 0건/오류 시 운영자 텔레그램으로 경고. 상태가 `/health` 명령으로 조회 가능.

### FR-D5. 관리 명령 — P1
운영자 전용: 재색인, 어댑터 on/off, 특정 매물 재분석, 통계 조회(일별 수집/분석/알림 건수).

> 결정(2026-07-09, 발주자): 수집 조사(10번 §7)의 반자동 권고에도 불구하고 **완전 자동(RPA) 원안 유지**. 개인 이용 + 저빈도 운영으로 제재 리스크를 감수 가능하다고 판단. 계정 제재 리스크는 발주자가 인지·수용함.

### FR-D6. 자동 채팅 (판매자 문의 자동 발송) — P2
Watch에 자동문의 옵션과 **구매 의사 가격 상한**이 설정되어 있고 매물이 필수 조건을 모두 충족하며 점수가 자동문의 임계값(알림 임계값보다 높게)을 넘으면, 본인 계정의 로그인 세션(RPA)으로 판매자에게 상세 정보 요청 메시지를 보낸다. 자동 결제·구매 확정은 하지 않는다.
- **AC**: 기본 동작은 **사전 승인 모드** — 알림의 [문의 보내기] 버튼을 눌러야 발송. 완전 자동 발송은 Watch별 명시적 opt-in.
- **AC**: 메시지 내용은 매물 속성 기반 템플릿(미확인 조건 질문 + 가격 제시)이며, 발송 전문과 시각이 기록됨.
- **AC**: 계정 보호를 위한 발송 빈도 상한(기본 시간당 2건, 일 5건)을 강제. 플랫폼별 지원 여부는 `10-collection-research.md`의 리스크 평가 결과를 따름.

## E. 비기능 요구사항 (NFR)

| ID | 항목 | 요구 | 비고 |
|---|---|---|---|
| NFR-1 | 하드웨어 | 단일 머신(16GB RAM, 소비자용 GPU 8GB 이하 또는 CPU-only)에서 전체 스택 구동 | "경량" 목표의 정의. VL은 GPU 없으면 처리량 축소 허용 |
| NFR-2 | 분석 지연 | 매물 1건 파이프라인 완주 p95 < 60초 (VL 포함) | |
| NFR-3 | 수집 예절 | 기본 수집 주기 30분(최소 15분), 플랫폼당 분당 요청 수 상한 설정 필수, 지수 백오프, 명시적 User-Agent | 저빈도 운영은 확정 전제. 위반 빌드는 배포 불가 |
| NFR-4 | 법적 준수 | robots.txt/약관 검토 결과 문서화 선행, 금지 경로 미사용, 수집물 미재배포 | `10-collection-research.md` 승인 전 해당 플랫폼 수집 코드 머지 금지 |
| NFR-5 | 개인정보 | 판매자 식별정보 최소 수집(닉네임·프로필 사진 저장 안 함), 매물 원문은 90일 후 파기 | |
| NFR-6 | 장애 격리 | 한 어댑터 장애가 다른 플랫폼 수집·분석·알림에 영향 없음 | |
| NFR-7 | 재현성 | LLM/VL 프롬프트·모델 버전이 AnalysisReport에 기록됨 | 모델 교체 시 품질 회귀 추적 |
| NFR-8 | 테스트 | 스코어링·정규화·별칭 매칭은 단위 테스트, LLM 추출은 골든셋 회귀 평가를 CI에 포함 | |
